# OpenManus-gui 脚本说明

本目录为 [OpenManus](https://github.com/FoundationAgents/OpenManus) 的课程定制副本（**gui** 侧重 **GUI-Plus 视觉操作**与增强版浏览器自动化）。项目安装与上游说明见 [README_zh.md](./README_zh.md)。

与 [OpenManus-cy](../OpenManus-cy/脚本说明.md) 的核心差异：`app/tool/browser_use_tool.py` 集成了 DashScope **gui-plus** 视觉模型，支持截图理解、坐标点击、智能填表，并以携程机票查询为典型演示场景。

## 目录结构

```
OpenManus-gui/
├── config_paths.py         # 统一路径配置
├── main.py                 # 主入口：通用 Manus Agent
├── app.py                  # Web UI 入口（FastAPI）
├── run_mcp.py              # MCP 客户端
├── run_mcp_server.py       # MCP 服务端
├── run_flow.py             # 多 Agent 规划流
├── sandbox_main.py         # Docker 沙箱 Agent
├── static/                 # Web UI 资源 + 教程截图（携程页面.png）
├── scripts/
│   ├── tutorial/           # GUI-Plus 入门教程
│   └── tests/              # 浏览器自动化测试脚本
├── app/
│   ├── agent/              # Agent 实现
│   └── tool/
│       └── browser_use_tool.py   # ★ GUI-Plus 增强浏览器工具
├── protocol/a2a/app/       # A2A 协议服务
└── examples/               # 上游用例示例
```

## 运行前提

```powershell
# 安装依赖
d:/ai_script/.venv/Scripts/python.exe -m pip install -r requirements.txt

# 浏览器驱动
d:/ai_script/.venv/Scripts/python.exe -m playwright install

# API Key（GUI-Plus 使用 DashScope）
$env:DASHSCOPE_API_KEY="your-dashscope-key"

# 配置 LLM
copy config\config.example.toml config\config.toml
```

在 `config/config.toml` 中配置 `[llm]`。浏览器视觉操作额外依赖 **gui-plus** 模型（DashScope 兼容接口）。

> **注意**：`scripts/tests/` 下脚本会启动真实浏览器并访问携程等网站，运行前请确保网络可用。建议在**项目根目录**执行，以便 `debug_html/` 调试输出路径正确。

### GUI-Plus 输出格式

模型返回严格 JSON，包含 `thought`、`action`（`CLICK` / `TYPE` / `SCROLL` / `KEY_PRESS` / `FINISH` / `FAILE`）及对应 `parameters`。详见脚本内 system prompt。

## scripts/tests/ — 浏览器自动化测试

均直接调用 `app.tool.browser_use_tool.BrowserUseTool`，用于验证不同操作策略。

| 脚本 | 测试重点 |
|------|----------|
| `test_simple_actions.py` | 简化接口 `click` / `type`（推荐入门） |
| `test_smart_mode.py` | HTML 分析智能定位（`smart_click`） |
| `test_vision_mode.py` | 纯 GUI-Plus 视觉模式 |
| `test_gui_plus.py` | GUI-Plus 视觉模式机票查询（简化流程） |
| `test_vision_click.py` | `vision_click` 视觉点击 |
| `test_date_picker.py` | 日期选择器元素提取与编号 |
| `test_direct_click.py` | 绕过模型的直接坐标点击（调试用） |

```powershell
# 从项目根目录运行
d:/ai_script/.venv/Scripts/python.exe scripts/tests/test_simple_actions.py
d:/ai_script/.venv/Scripts/python.exe scripts/tests/test_smart_mode.py
d:/ai_script/.venv/Scripts/python.exe scripts/tests/test_vision_mode.py
```

### 三种操作策略（browser_use_tool 内部）

```
用户调用 click / type
    │
    ├─► 1. HTML 智能定位（JavaScript 分析 DOM）
    │       成功 → 直接操作元素
    │
    └─► 2. GUI-Plus 视觉回退
            截图 → gui-plus 模型 → JSON 坐标/文本 → 执行 CLICK/TYPE
```

日期选择器、弹窗等动态元素优先走 **GUI-Plus 视觉模式**识别。

## 核心模块：browser_use_tool.py

本版本最重要的定制文件，在标准 browser-use 基础上扩展：

| 能力 | 方法/接口 | 说明 |
|------|-----------|------|
| 简化操作 | `click(element_description=...)` | Agent 推荐接口，内部自动选择策略 |
| 简化输入 | `type(element_description=..., text=...)` | 描述输入框并填文本 |
| 视觉操作 | `_execute_vision_action()` | 截图 + gui-plus 模型推理 |
| 智能点击 | `_execute_smart_click()` | HTML/JS 元素定位 |
| 调试输出 | `debug_html/` | 运行时自动保存截图与 HTML（已加入 .gitignore） |

Manus Agent（`main.py`）默认挂载此工具，因此完整 Agent 也具备 GUI-Plus 能力。

## 常见问题

1. **gui-plus 报错**：确认 `DASHSCOPE_API_KEY` 已设置，且账户已开通 gui-plus 模型。
2. **浏览器启动失败**：执行 `playwright install`。
3. **坐标点击不准**：属视觉模型固有问题，可对比 `test_smart_mode.py`（HTML 定位）与 `test_direct_click.py`（硬编码坐标调试）。
4. **debug_html 目录**：运行测试后自动生成，已在 `.gitignore` 中忽略，可随时删除。

# 每日知识点整理

将桌面暂存的零星知识点整理成当天一篇 Obsidian 笔记。只做本 Skill 规定的路径与步骤，不要改动其他功能或目录。

也可由 `runtime\run_digest.py`（任务计划每日 22:00）无人值守调用。

## 路径（固定）

| 用途 | 路径 |
|------|------|
| 输入暂存 | `C:\Users\85325\Desktop\想法暂存.txt` |
| 输出目录 | `D:\陈总的ob仓库\04_每日知识点整理` |
| 输出文件 | `YYYY-MM-DD-知识点整理.md`（日期为整理当天，本地时区） |

编码一律 UTF-8。写入中文后如发现乱码，立即修正为正确 UTF-8。

## 执行清单

复制并逐项勾选：

```
进度:
- [ ] 1. 读取暂存
- [ ] 2. 解析与去重
- [ ] 3. 联网检索并撰写说明
- [ ] 4. 写出 Markdown
- [ ] 5. 清空暂存
```

### 1. 读取暂存

- 读取 `想法暂存.txt`。
- 若文件不存在、为空、或去掉空白后无实质内容：简短告知「今日无暂存知识点」，**到此结束**。不要创建空 MD，不要清空不存在的文件。

### 2. 解析与去重

暂存格式通常为多条块，形如：

```text
---
2026-07-19 16:42
知识点原文或问题
---
```

解析规则：

- 按 `---` 分块；若没有分隔符，则按空行分段，每段一条。
- 每条取「正文」（时间戳行可保留为来源时间，不作为知识点标题）。
- 去重：正文去首尾空白后，大小写不敏感、完全相同的只保留一条（保留最早时间戳）。
- 表述几乎相同（仅标点/空格差异）合并为一条，保留信息更完整的原文。

### 3. 联网检索并撰写说明

对每个知识点：

1. 使用联网搜索获取可靠、稍详细的解释（优先权威文档、教材式说明；避免营销文与过时论坛传言）。
2. 用中文撰写学习笔记，**必须**按下列三个要点展开（见下方模板），不要只写一句话敷衍。
3. 不要编造具体论文数据、版本号或「官方定义」；搜不到则如实写「暂未找到权威简述」，并基于已知概念作谨慎说明且标明不确定性。

三个要点的写法：

- **名词解释**：先给清晰定义，再写 2～4 句展开（原理/构成/和相近词的区别，视概念而定）。
- **常见应用**：列出 2～4 个真实常见的使用场景或落地方式，可简短举例。
- **其他类似应用或概念**：写出 2～4 个相关、易混淆或可类比的概念/技术，并各用一句话说明与本知识点的关系或差异。

整体比百科词条短、比一句话定义长；不要写成论文或超长专题。

### 4. 写出 Markdown

- 确保输出目录存在；不存在则创建 `D:\陈总的ob仓库\04_每日知识点整理`。
- 目标文件：`D:\陈总的ob仓库\04_每日知识点整理\YYYY-MM-DD-知识点整理.md`。
- 若同名文件已存在：**整文件覆盖**为本次整理结果。
- 一天一篇总览，按知识点分节编号。

使用以下模板（按实际条目增减；三个要点标题固定，不要改名或省略）：

```markdown
# YYYY-MM-DD 知识点整理

> 来源：想法暂存 | 整理时间：HH:mm

## 1. [知识点短标题]

**原句：** [暂存中的原文]

**名词解释：**
[定义 + 2～4 句展开]

**常见应用：**
- [场景或用法 1]
- [场景或用法 2]
- [场景或用法 3]

**其他类似应用或概念：**
- [相关概念 1]：[与本知识点的关系或差异]
- [相关概念 2]：[与本知识点的关系或差异]
- [相关概念 3]：[与本知识点的关系或差异]

## 2. [下一个知识点]
...
```

短标题从原句提炼，宜短；原句尽量保留用户原文。

### 5. 清空暂存

- MD 成功写入后，将 `C:\Users\85325\Desktop\想法暂存.txt` **清空**（写入空文件或清空内容）。
- **不要**创建 `.bak` 或其它备份。
- 若写出 MD 失败，**不要**清空暂存，并说明失败原因。

## 完成时回复用户

用两三句话说明：处理了几条、输出文件完整路径、暂存已清空（或因无内容未执行）。

- 不要改 Obsidian 库内其它文件夹。
- 不要提交 git、不要写项目说明 md、不要写测试脚本。
